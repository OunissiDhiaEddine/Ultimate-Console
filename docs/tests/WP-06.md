# WP-06 · System info — manual checklist (about 5 minutes)

Run on the real PC from a normal (non-admin) terminal, with `uc-probe.exe`
from the CI artifact or `cargo build --release`. Keep Task Manager open on the
**Details** tab (add the "GPU" column if it is hidden) to compare numbers.
The first line of every run shows `--` for CPU/GPU: that's expected, there is
nothing to compare against yet.

1. **System line only**
   `uc-probe sysinfo --count 5`
   - [ ] CPU % and RAM used/total are close to Task Manager's Performance tab.
   - [ ] GPU % shows a number (not `--`) from the second line on.
   - [ ] "sample took" stays under ~50 ms after the first line.

2. **A game or GPU load**
   Start a game (or a GPU benchmark / YouTube 4K video in a browser). Find its
   PID in Task Manager → Details.
   `uc-probe sysinfo <pid> --count 10`
   - [ ] Name is the game's `.exe`.
   - [ ] CPU % is within a few points of Task Manager's CPU column.
   - [ ] GPU % is within a few points of Task Manager's GPU column.
   - [ ] "ws" matches Task Manager's "Memory (active private working set)"
         roughly (ws is a bit higher, it includes shared pages); "private"
         matches the "Commit size" column.
   - [ ] Uptime looks right.

3. **Several processes at once**
   `uc-probe sysinfo <steam pid> <game pid> <explorer pid>`
   - [ ] One line per PID, each with plausible numbers.

4. **Edge cases**
   - [ ] A PID that doesn't exist (e.g. `uc-probe sysinfo 3`) prints
         "not readable" instead of crashing.
   - [ ] An elevated process (e.g. an admin Command Prompt's PID) still shows
         CPU/RAM; if it says "not readable", note it here.
   - [ ] Close the game during a long run (`--count 30`): its line switches to
         "not readable", the system line keeps going.

Report anything that is off by more than ~5 points, with the probe output.
