# WP-02 manual check: Android TV (about 10 minutes)

Download the `ultimate-console-<sha>` artifact from the PR's CI run, unzip it,
and open PowerShell there. Use a scratch folder so nothing real is touched:

```powershell
$env:UC_HOME = "$env:TEMP\uc-test"
```

**On the TV first** (IRIS / Android TV): Settings → Device Preferences →
About → press *Build* 7 times. Then Developer options → turn on
*USB debugging* and *Network debugging* (some TVs call it *ADB over network*).
Note the TV's IP (Settings → Network). While there, look for
*Network standby*, *Wake on LAN* or *Wake on Wi-Fi* and turn it on.

Every command prints log lines to the console; keep them if something fails.

1. **Discover**: `.\uc-probe.exe tv discover`
   → the TV is listed with its IP. Note whether it says `ADB on 5555` or
   `ADB not advertised` (both are fine; the second just means typing the IP).
   Windows Firewall may ask about `uc-probe` the first time: allow on private networks.
2. **Pair**: `.\uc-probe.exe tv pair <TV-IP> --save`
   → the TV shows *Allow USB debugging?*. Tick *Always allow from this
   computer* and press *Allow*. The probe prints manufacturer, model,
   Android version and `mac: AA:BB:…`. **Write down the Android version.**
   If the MAC says "not found", run `arp -a <TV-IP>` and put it in the config
   by hand (`tv.mac` in `%TEMP%\uc-test\config\config.toml`).
3. **Pair again**: run the same command once more → no prompt on the TV this time.
4. **State**: `.\uc-probe.exe tv state` → `awake`.
5. **Sleep**: `.\uc-probe.exe tv sleep` → the TV turns its screen off.
   Then `.\uc-probe.exe tv state` → `asleep` (or `dozing`), or `unreachable`
   if the TV drops off the network when asleep (note which).
6. **Wake (the important one)**: wait **2 minutes** with the TV asleep so it
   goes into deep sleep, then `.\uc-probe.exe tv wake` → the TV turns on.
   Note the printed time, attempts and WoL packets.
7. **WoL alone**: put the TV to sleep with its remote, wait 2 minutes, then
   `.\uc-probe.exe tv wol` → does the TV turn on (or at least come back on the
   network, so `tv state` answers)? Note yes/no.
8. **Fast sleep (suspend path)**: with the TV on,
   `.\uc-probe.exe tv sleep-fast` → the TV turns off and the probe prints the
   time taken. It must be under the 1500 ms budget; note the number.
9. **Run**: `.\uc-probe.exe tv run getprop ro.product.model` → the model name.
10. **Not paired**: on the TV, Developer options → *Revoke USB debugging
    authorisations*, then `.\uc-probe.exe tv state` → error saying the TV has
    not authorised this PC (no long wait). Pair again with step 2 after.

Report back: Android version, steps 5–8 results (state when asleep, wake
time, whether WoL alone works, sleep-fast time), and the name of the
network-standby setting if there is one.

Clean up: `Remove-Item -Recurse "$env:TEMP\uc-test"`.
